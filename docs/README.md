易支付接入的设备参数、单笔/列表响应及真实交易号规则见[接口参考](wiki/V1-16-易支付V1接口参考.md)。平台查询失败的异常语义、监听事件键与真实交易号的区别见[插件开发](wiki/V1-23-支付插件开发.md)；实施和静态检查范围记录在实现计划，不表示真实支付联调已验收。

维护时先读取 `docs/implementation-plan.md` 顶部当前状态及 AGENTS.md 最新约定。指定开发库已于 2026-10-18 完成新版基线整理，测试库随后单独对齐并核对，两者均为 25/25 complete、initialized；旧节点中的 76 条迁移记录及“尚未处理”仅描述当时现场。后续仍须实时核对目标库，不能用历史过程记录代替当前结果。本次环境整理不改变正式安装器的版本和非空保护。

当前插件合同统一从[支付插件开发](wiki/V1-23-支付插件开发.md)、[配置字段规则](wiki/V1-24-config-schema字段规则.md)和[主动采集与会话协作](wiki/V1-25-主动采集与会话协作.md)阅读：PayPluginInterface 管元信息和配置，PaymentInterface 管支付动作及统一 notify，ReceiptCollectorInterface 管主动查询和保活。预登录由代码元信息 prelogin 声明，按订单采集，每账号每轮单次查询最新最多 200 条，登录状态永久文件缓存。

插件单项读取使用已同步映射并核对固定文件、接口及实际编码，不间接装配整个目录；表单同步检查和目录刷新保留。付款、支付号回调及退款共用原单快照的结构和归属核验，各动作及锁内交易保护保持；查询响应只在最外层包装 code/msg，详情见上述插件合同及[数据约定](wiki/V1-22-支付链路与数据约定.md)。

插件 init 只接收配置，订单及平级 _env/_submit_type 由动作传入；notify 统一返回结果列表，按通道处理整批流水并逐笔确认。配置编辑允许读取待修正值；确认结果明确关联通道与订单。采集失败以 reason/retry_after 表达分类和重试，可补充来源、阶段、平台错误码、说明及 HTTP 状态。平台协议由插件/SDK 解释，服务统一记录和展示；说明脱敏后最多保留 2048 个 UTF-8 字节，恢复后保留最近错误和恢复时间。完整字段合同见[主动采集](wiki/V1-25-主动采集与会话协作.md)，实现和静态检查范围见 `docs/implementation-plan.md` 最新节点。

内部采集 notify 的 records/orders 批次复用本轮调度候选，不按流水时间另查订单；上下文仍只有通道及可选支付号，跨通道歧义与逐笔交易核验保留。epay 的 mapi 材料按 payurl、qrcode、urlscheme 优先选择并校验，退款拒绝保留受限脱敏技术诊断，详见[插件合同](wiki/V1-23-支付插件开发.md)。

商户通知保留目标授权、端口及 DNS/IP 检查和连接绑定；插件 SDK 按配置平台地址正常连接，支持内网部署，无须新增放行参数。两者共用 TLS、超时、大小和禁止自动重定向/代理的传输规则，详见[插件网络合同](wiki/V1-23-支付插件开发.md)。

签名表单的拆分和解码复用已有 Guzzle，项目保留薄层协议校验；最终通知/回跳 URL 由消息入口统一组装并检查实际 query 和长度，删除认领端重复解析。冻结签名、订单身份、通知租约及发送前网络目标检查继续保留，详见[商户通知](wiki/V1-10-商户通知与人工处理.md)。

产品/动作由插件按实际付款准备分支声明并冻结，订单技术信息直接展示原值。采集按本轮唯一版本批读快照，复用待写内存摘要；监听结果的付款时间只使用 receipt.paid_at；普通平台订单结果使用外层 paid_at，平台未提供时为 null。两类确认都保留锁内交易核验。

付款确认在支付单列保存时间和渠道交易号，personal_receipt 不再保存同义重复键；金额证据与流水身份保持。收钱吧复用本批轮转读取，凭证候选只保存摘要与密码；通知过期候选满额即返回。插件缺失清理保留全部引用保护，通道列表仅投影需要的字段；本组调整不增加表列或运行时兼容层。

单个插件配置按编码读取已同步的数据库定义，列表与单项共用安装及同步检查；关联通道数一次分组统计。插件参数保存复用 Editor 已锁配置，易支付按支付号查询复用已读订单；保留版本、归属及交易核验。相关接口与读取边界见[版本变化](wiki/V1-28-版本更新与文档维护.md)。

通道测试复用保存快照，选路批量读取候选后在锁内复核；HTTP 回调日志直接关联单条流水，删除关联流水分页。快照保留正文与版本，不再保存未使用的摘要；商户响应只读取一次，本地关闭在交易事务内核验管理员。

配置启用复用 Editor 已锁定的模型，建单复用事务内的业务单及路由方式结果；执行认领/回写各自在锁内处理到期。回跳在一个一致性事务中核对首次 ACK 并签名，标准流水格式检查集中在输入边界。插件发现一次核验固定代码合同，执行创建独立实例，仅装配配置；schema 值校验由保存和启用入口承担。详见公开开发规范与支付链路文档。

配置列表直接使用通道查询入口，后台详情仅返回所需字段；到账流水按 pay_no 读取最终绑定，金额偏移由原金额与识别金额计算。内部采集确认返回笔数，SDK 仅输出插件实际消费的归一化账单字段。

通知仅核对当前尝试，完整 URL 每次认领构造一次；响应保留受限正文及截断标记。采集摘要只展示实际活动和连续失败批次，不推算账号下次调度。候选解析在批次内复用，收钱吧范围身份由 SDK 的同一个规则生成，具体见商户通知和主动采集文档。

站内导航与编辑交互按明确边界处理：前端直接使用本站返回的跳转地址，目标入口校验订单权限；后台接入地址沿用浏览器当前站点。普通业务冲突可修正后重试，配置版本过期使用 40910；只有写入结果未知才阻止不安全重投。通道字段共用一次输入验证，插件配置直接按 schema 读取原生值。具体说明见[开发规范](wiki/V1-21-开发环境与目录结构.md)与[收银台扩展](wiki/V1-30-收银台页面与扩展.md)。

商户回跳只检查地址格式和可选域名，不套用服务器出站端口/IP 限制；通知发送仍保留网络目标检查。SDK 协议字段由 PSR-7/Guzzle 处理，公共 HTTP 层保留目标站点、TLS、请求/响应大小及超时限制。当前合同见[接口参考](wiki/V1-16-易支付V1接口参考.md)。

通道配置写入先按 ID 取齐涉及的支付方式锁；退款区分准备失败与执行后未知；维护进程按单隔离业务拒绝并继续扫描。退款和运行边界见[接口参考](wiki/V1-16-易支付V1接口参考.md#退款申请)及[后台任务](wiki/V1-18-部署与后台任务.md)，验证范围见实现计划最新节点。

payment:work 只负责商户通知、订单到期及有限运行文件清理，付款准备由下单和收银台请求触发。必要异常隔离保留在到期订单、单次通知及插件任务边界；采集任务异常只记录技术日志，不猜测平台原因或受影响通道。数据库、初始化及心跳等共享故障仍明确上抛；不新增队列、调度框架或数据表。运行规则见[后台任务](wiki/V1-18-部署与后台任务.md)，开发边界与真实验收范围记录在本地开发规范和实现计划。

本地实施资料位于 `docs/order-driven-collection-2026-10-11.md` 与 `docs/implementation-plan.md`；实际验证、数据库切换和待联调范围以最新交接节点为准。标记为“历史资料/历史节点”的方案与报告仅保留当时事实，旧接口、分页、会话存储及验收结果不作为当前开发合同。在线 Wiki 需要另行发布，本地文档修改不表示远程内容已经同步。

本地实施方案：`docs/payment-data-model-redesign-2026-10-13.md`。已按用户确认实施通道范围分配/匹配、保留 JSON 快照、预约退役和公开收银台模块。代码、隔离验证及当前数据库的实际进度见实现计划；本地维护资料继续遵循 Git 忽略规则。

访问规则：HTTP/HTTPS 不作为手机通知准入条件，当前主机共用固定会话；后台和收银台不比较浏览器 Origin 与后端协议，仍执行认证、CSRF、跨站标识和载荷检查。当前部署说明见 [部署与后台任务](wiki/V1-18-部署与后台任务.md)，实际同步范围见实现计划。

验证规则：普通输入统一使用 think\Validate；手机通知共用 SmsForwarderValidator，读取框架 POST 参数，不依赖服务器重写参数或独立消息 DTO。字段验证与签名、平台消息解释的边界见[开发分层](wiki/V1-21-开发环境与目录结构.md#分层约定)及[插件合同](wiki/V1-23-支付插件开发.md)；本地维护资料中的验证器审查范围见实现计划。

监听应答：支付宝手机和微信手机/PC 插件成功返回 HTTP 200、正文 `200`，业务拒绝返回 HTTP 200、正文 `400：错误原因`；通知工具的成功关键字填 `200`。业务网站接收付款通知时仍返回 `success`。完整说明见[微信监听](wiki/V1-11-微信手机与PC监听.md#通知应答)及[支付宝监听](wiki/V1-12-支付宝手机监听.md)。
