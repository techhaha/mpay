公开正文的唯一维护源为 docs/wiki；同步方法见 [Wiki 工具说明](wiki/tools/README.md)。设计讨论、实现计划、交接和环境验证记录仍保存在 docs 的维护资料中，与面向用户的手册分开。

当前插件合同统一从[支付插件开发](wiki/V1-23-支付插件开发.md)、[配置字段规则](wiki/V1-24-config-schema字段规则.md)和[主动采集与会话协作](wiki/V1-25-主动采集与会话协作.md)阅读：三个接口，预登录由代码元信息 prelogin 声明，按订单采集，每账号每轮单次查询最新最多 200 条，登录状态永久文件缓存。

插件执行统一初始化，配置编辑允许读取待修正值；确认结果明确关联通道与订单，采集失败只传 reason/retry_after，展示状态由服务映射。实现和静态检查范围见 `docs/implementation-plan.md` 最新节点。

本地实施资料位于 `docs/order-driven-collection-2026-10-11.md` 与 `docs/implementation-plan.md`；实际验证、数据库切换和待联调范围以最新交接节点为准。标记为“历史资料/历史节点”的方案与报告仅保留当时事实，旧接口、分页、会话存储及验收结果不作为当前开发合同。在线 Wiki 需要另行发布，本地文档修改不表示远程内容已经同步。

本地实施方案：`docs/payment-data-model-redesign-2026-10-13.md`。已按用户确认实施通道范围分配/匹配、保留 JSON 快照、预约退役和公开收银台模块。代码、隔离验证及当前数据库的实际进度见实现计划；本地维护资料继续遵循 Git 忽略规则。

本轮全局审查记录：`docs/global-code-audit-2026-10-13.md`，包含输入校验、插件运行参数、交易异常恢复、SQL 性能与实际页面验收的范围和证据；最终结果以实现计划最新节点为准。

访问规则：HTTP/HTTPS 不作为手机通知准入条件，当前主机共用固定会话；后台和收银台不比较浏览器 Origin 与后端协议，仍执行认证、CSRF、跨站标识和载荷检查。当前部署说明见 [部署与后台任务](wiki/V1-18-部署与后台任务.md)，实际同步范围见实现计划。

验证规则：普通输入统一使用 think\Validate；手机通知共用 SmsForwarderValidator，读取框架 POST 参数，不依赖服务器重写参数或独立消息 DTO。字段验证与签名、平台消息解释的边界见[开发规范](development-standards.md)及[插件合同](p2-plugin-contracts.md)，24 个验证器的本轮审查范围见实现计划。

监听应答：支付宝手机和微信手机/PC 插件成功返回 HTTP 200、正文 `200`，业务拒绝返回 HTTP 200、正文 `400：错误原因`；通知工具的成功关键字填 `200`。业务网站接收付款通知时仍返回 `success`。完整说明见[微信监听](wiki/V1-11-微信手机与PC监听.md#通知应答)及[支付宝监听](wiki/V1-12-支付宝手机监听.md)。
