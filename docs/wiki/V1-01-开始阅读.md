# 第一次使用：从安装到收款

本文档适用于 **MPAY V1 的 ThinkPHP 重构版（代码分支 `v1`）**。旧版安装包与 V2 使用不同的结构和流程，请勿混用。重构版目前为开发版本，真实平台接入需按实际账号和设备完成核对；功能范围见[能力清单](V1-02-项目介绍与能力清单.md)。

## 第一次只走这条路线

先配置一个业务网站、一种支付方式和一个收款通道。安装时已经创建默认应用及默认轮询组，第一笔收款不需要自己设计分组、权重或接口签名。

| 顺序 | 现在做什么 | 做完应看到什么 |
| --- | --- | --- |
| 1 | [准备资料](新手-准备资料与名词.md)，确认有支持易支付 V1 的业务网站 | 有 MPAY 域名、数据库资料和自己的收款方案 |
| 2 | [准备网站](新手-宝塔建站准备.md)：上传程序、安装依赖、设置 public、路由与访问地址 | 浏览器能打开 MPAY 的 `/install` 页面 |
| 3 | [网页安装四步](V1-03-安装与环境要求.md) | 能用自己设置的管理员账号登录；已有默认应用 |
| 4 | [新增通道](V1-06-收款通道与支付方式.md)，完成所选插件的手机转发或账单配置 | 通道已启用，设备转发或主动查询已按对应教程配置 |
| 5 | 按[后台任务指南](V1-18-部署与后台任务.md#准备命令中的路径)复制两条命令，分别添加任务 | 两个任务运行中，后台“运行维护”有近期活动 |
| 6 | [配置默认应用](V1-05-应用与接入凭证.md)，把地址、PID、KEY 填入[业务网站](V1-15-业务网站接入.md) | 允许域名已保存，应用路由预览能选到通道 |
| 7 | [从业务网站完成第一笔收款](V1-04-完成第一笔收款.md) | 实际账户到账、MPAY 支付成功、业务网站处理成功 |

每次只完成当前一行，达到右侧结果再继续。某步失败时，在那一页按提示处理，不需要重装整个系统。**能登录后台只是安装完成，完成第 7 步才表示这套接入已经跑通。**

如果还没有业务网站，可以先完成安装和收款配置；MPAY 后台没有让管理员随意创建购买订单的入口。收款订单由支持易支付 V1 的业务网站发起，自行开发时再阅读接口文档。

暂时不用阅读：自定义轮询策略、数据库字典、插件开发和命令行安装。以后有多网站独立选路或二次开发需求，再按下面入口查看。

## 五个常用概念

- **应用**：你的商城、发卡站或其他业务网站。每个应用拥有自己的 PID、KEY 和订单。
- **支付方式**：支付宝、微信支付等分类；分类存在不代表已有对应插件可收款。
- **插件**：解释平台协议、提供付款信息、识别到账的适配代码。
- **通道**：一组实际可选用的收款配置。通用限额属于通道；插件参数独立绑定该通道。
- **轮询组**：为一次下单选择可用通道。首次安装已有默认组，新通道自动加入。

“商户”在这套单收款主体系统里，通常指你自己的商城等业务网站。通道通知负责告诉 MPAY 有人收款；商户通知负责告诉业务网站哪笔订单已付。两者的地址和密钥分别配置。

## 如何判断已经跑通

收款账号有实际到账、MPAY 原订单显示成功、业务网站原订单处理成功，是三个需要分别核对的结果。二维码出现、HTTP 200、设备消息到达或浏览器返回页面，均不能单独作为支付成功依据。
