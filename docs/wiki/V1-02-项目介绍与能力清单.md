# 项目介绍与能力清单

MPAY 将收款码、到账识别、业务订单与网站通知衔接起来。资金由实际微信、支付宝或收款服务商账户接收，MPAY 记录与核对交易，不提供平台余额托管或结算。

## 适合的场景

一个收款主体管理多个业务网站，希望每个网站使用独立 PID/KEY、分别查看订单，并按需要选择不同通道。系统采用单管理员后台，页面和接口由同一 ThinkPHP 应用提供。

| 模块 | 已提供的能力 |
| --- | --- |
| 安装 | 网页环境检查、数据库检查、建表、管理员与默认应用初始化、中断续装 |
| 应用 | 独立 PID/KEY、密钥重置、允许的通知/返回域名、默认与自定义路由 |
| 通道 | 四步新增、独立插件配置、启停、指定通道付款测试、单笔范围、每日限额/笔数、可用时段 |
| 路由 | 默认自动绑定、顺序轮询、权重随机、默认优先、只读选路预览 |
| 交易 | 业务单与支付单、收银台、到账识别、订单查询/导出、人工确认与本地关闭 |
| 通知 | 商户通知重试、暂缓/放行、立即发送、单次补发、响应片段与首次确认记录 |
| 运行 | 两个原生 CLI 守护入口、按订单采集、插件账号与登录态复用、运行诊断及操作审计 |
| 扩展 | 插件固定目录发现、元信息入库、按 schema 自动展示表单、本地平台 SDK |

## 内置插件

| 插件 | 编码 | 支持方式 | 到账来源 | 需要准备 |
| --- | --- | --- | --- | --- |
| 微信手机/PC 收款监听 | `wxpay_receipt` | `wxpay` | 安卓通知或约定格式的 PC 消息 | 收款码、通知工具、专属通知密钥 |
| 支付宝手机收款监听 | `alipay_receipt` | `alipay` | 安卓通知 | 收款码、通知工具、专属通知密钥 |
| 支付宝账单收款 | `alipay_bill_receipt` | `alipay` | PHP 主动查询账单 | 账单权限、AppID、账单用户 ID、RSA2 凭证 |
| 收钱吧码牌收款 | `shouqianba_receipt` | `alipay`、`wxpay` | PHP 主动查询码牌流水 | 可登录的平台账号、商户/门店范围、收款材料 |

云闪付使用编码 `unionpay`，可以管理其支付方式字典，但当前内置插件没有云闪付适配。只有安装并启用支持该编码的插件后，才能建立可用通道。

## 能力边界

- 对外接入协议为易支付 V1；不提供易支付 V2、多商户入驻、余额清算或转账产品。
- 退款请求会派发给原订单插件；当前四个监听插件均不支持接口退款。
- 收银台提供普通扫码、手动备注，以及支付宝账单插件的自动填写金额和备注入口；具体模式由插件声明，不等于支持 V2 的全部支付产品。
- 不需要 Redis、消息队列或 Workerman；平台查询与业务通知由两个 PHP CLI 命令运行。
- 批量流水逐笔匹配，一条流水只绑定一笔订单，不合单、不拆单。数据库只保存成功绑定的流水。

## 实现与验证范围

本版本已具有上述代码与页面，隔离测试和合成收款不能替代真实设备及平台验证。安卓通知模板、PC 客户端版本、支付宝账单权限/响应及收钱吧平台变化，均需在部署者的实际接入环境核对。不要将本页理解为平台可用性或收款成功率保证。

Gitee 和 GitHub 源码仓库的默认分支均为 `v1`。旧分支和旧发行包仍可能对应其他版本，获取代码或安装包时须核对版本；旧版数据不能直接覆盖重构版新装数据库。
