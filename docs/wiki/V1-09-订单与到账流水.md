# 订单与到账流水

“交易订单”是日常入口，按应用、订单号、支付方式、订单创建日期、订单状态等条件查询。订单状态在同一列合并展示支付和退款进度；更多筛选包含通道、轮询组、下单 PID 及商户通知状态。

列表直接展示业务单号与商户订单号、应用与商品、支付方式、收款通道、订单金额与已确认实收、订单状态、商户通知、创建与付款时间。未确认实收显示“—”；尚未选择支付方式时显示“未选择”。付款时间为空不代表零元支付或成功。

点击蓝色业务单号或行右侧“详情”打开订单，查看支付单号、下单 PID、提示付款金额、收款依据和来源流水号；在“商户通知”页签查看发送记录，列表徽章仅展示状态。商户订单号可以直接选中文字复制。交易时间上行为创建时间，下行为付款时间，悬停可查看含义。长文字悬停可查看完整内容；窄窗口可横向滚动表格。

![订单详情](assets/order-detail.jpg)

## 1. 用买家提供的订单号找订单

1. 点击左侧“交易订单”。
2. 先看编号来源：商城提供的号码选“商户订单号”；MPAY 的 B 开头号码选“业务单号”；P 开头号码选“支付单号”。
3. 把完整号码复制到“订单号”输入框。不要把商品名或金额填在这里。
4. 核对“创建日期”包含下单日期，再点“查询”。默认日期范围不包含所有历史订单。
5. 找到结果后，核对应用、商品和金额，点击该行右侧“详情”。

没有结果时，先改日期和单号类型，不要立即判断订单丢失。多个应用可能使用相同的商户订单号，应同时选择正确应用。

## 2. 看懂详情中的三个金额

![成功订单详情（演示数据）](assets/tutorial/order-success.jpg)

| 位置 | 说明 | 实际操作 |
| --- | --- | --- |
| 订单原金额 | 商城要求支付的金额 | 与商城订单核对 |
| 提示付款金额 | 本次收银台要求付款者支付的金额 | 有金额识别偏移时可能比原金额略高 |
| 已确认实收 | 本次确认依据记录的收款金额 | 尚未确认时显示空值，不能当作已收款 |

详情下方的页签按用途查看：“订单概况”看通道和时间；“到账流水”看自动匹配依据；“商户通知”看商城是否应答；“处理记录”看人工操作等过程。支付成功的订单另有“退款记录”，查看可退额度和每次申请结果。

## 3. 更改每页数量或导出

在表格右下角点击“20 条/页”，可切换为 10、20、50、100 条。详情内的表格也有各自的分页，外层条数不会同时修改内层。

导出操作：先选择应用、支付方式、日期或状态并点击“查询”，确认结果符合需要，再点右上角“导出订单”。页面准备好文件后，浏览器下载 CSV；到浏览器下载列表打开它。单次最多 31 天、10000 条，超过时缩小日期或按应用分别导出。CSV 分别保留订单展示状态、原支付状态、退款情况、累计成功退款、未决退款占用和剩余可退金额；筛选及金额口径与列表、详情一致。CSV 包含支付方式编码，尚未选择时为空。导出的长订单号在电子表格中应按文本导入，避免变成科学计数法。

**完成检查：** 下载文件存在，表头可读，订单范围与刚才的筛选一致。只有页面弹出下载提示时，还要确认浏览器没有拦截下载。

## 订单状态与退款展示

列表与详情顶部共用“订单状态”，状态与金额在同一枚内容宽度徽章中展示，例如“已全部退款 · ¥0.20”“已部分退款 · ¥0.10”，不固定徽章宽度、不另起金额副行。处理中或待核实时附未决占用金额，退款未成功显示“支付成功 · 退款未成功”。列表的金额和状态列只设置最小宽度 130/180，余宽交给 Layui 自适应。原支付事实在详情“订单概况”的“支付状态”和 CSV 中保留；不把支付成功改写成未支付或支付失败。

订单徽章按稳定状态编码确定颜色，不根据中文文案猜测：支付成功为绿色，支付失败为红色，关闭、超时及全部退款为灰色，部分退款与处理中为蓝色，退款待核实为橙色。仅退款未成功时保留绿色付款成功事实，并附退款说明。

| 情况 | 主标签 | 辅助信息 |
| --- | --- | --- |
| 已付款、没有退款申请 | 支付成功 | 原付款金额保持 |
| 成功退回部分实付金额 | 已部分退款 | 累计已退金额 |
| 成功退回全部实付金额 | 已全部退款 | 累计已退金额 |
| 存在正在执行的申请 | 退款处理中 | 已退金额或未决金额 |
| 存在结果未知的申请 | 退款结果待核实 | 已退金额或未决金额 |
| 只有未执行或被拒绝的申请 | 支付成功 | 退款未成功 |

存在未知申请时优先显示待核实，其次是处理中，再按累计成功金额显示部分或全部退款。全退必须满足累计成功退款等于用户实际支付金额；剩余可退为零可能只是额度被未决申请占用，不代表已退款。成功退款之后的失败历史保留在记录中，不覆盖累计退款进度。状态悬停可查看累计已退和未决占用金额。

“订单状态”筛选中的“支付成功（含退款）”查询所有付款成功的订单；部分退款、全部退款、处理中、待核实选项按上述优先级查询当前进度。“退款未成功”只查询已有申请但没有成功退款或未决申请的订单。日期始终按订单创建日期，不是退款申请日期。退款请求返回后列表与详情重新读取，不自动再次申请退款。

## 后台申请退款

1. 在“交易订单”找到原订单，打开详情，确认已支付成功。
2. 点击底部“申请退款”，核对已确认实际支付、已退款、处理中或待核实金额以及剩余可退金额。
3. 退款金额默认填入剩余可退金额，可修改为较小金额；填写管理员密码，退款备注可留空。
4. 点击“确认申请退款”，在返回的“退款记录”页签查看结果。插件不支持或平台拒绝时会明确提示，不能把请求处理完成当成退款成功。

可退额度按**用户已确认的实际支付金额**计算，减去已成功、处理中和结果待核实的退款；失败或未执行的申请不占用额度。例如业务原金额 10.00 元、用户实际支付 10.01 元，尚无退款时可申请 10.01 元。缺少已确认实收依据时不能用原金额或提示金额补算。

支付成功且有剩余额度时统一提供入口，不根据插件名称隐藏；能否退款、是否接受部分退款由原订单插件和第三方平台决定。通道后来停用、改配置或更换插件，退款仍使用原支付单冻结的插件配置。当前监听插件没有原路退款接口，易支付平台插件按平台标准提交退款。

退款结果包括成功、未执行或拒绝、处理中、待核实。处理中或待核实仍占用金额，后台暂不接受新的退款申请；网络中断后先重新打开原订单查看记录，不换号重复申请。只有明确失败并排除原因后，才发起新的申请。平台拒绝或未知的脱敏说明在本次响应展示，刷新后按退款号、处理记录中的请求编号查询技术日志核对详情。

退款成功后，列表和详情顶部显示“已部分退款”或“已全部退款”，原支付状态仍为“支付成功”，详情概况和导出保留原收款事实。本功能不新增商户退款通知，也不修改原付款成功通知；业务网站需要自行核对其退款、发货或服务状态。“关闭订单”不会退款。退款接口接入见[退款申请](V1-16-易支付V1接口参考.md#退款申请)。

## 三类记录的区别

从通道“更多 → 测试”发起的付款也是普通订单，商品名为“通道收款测试”，保存所选应用的 PID。订单展示、状态、到账、人工操作、统计和导出均使用同一套规则，不设独立用途、徽章或筛选。所有订单仅依据是否提供通知地址决定是否创建异步通知；未提供时，列表显示“无通知地址”，悬停提示“未设置通知地址”。

| 记录 | 回答的问题 | 位置 |
| --- | --- | --- |
| 到账流水 | 哪条到账证据最终确认了哪笔订单？ | 订单详情、到账流水列表 |
| 商户通知 | MPAY 是否把结果发给业务网站，对方如何应答？ | 订单详情、交易订单上方的商户通知入口 |
| 通道回调日志 | 设备/平台向 MPAY 发来了什么类型的请求，是否通过校验？ | 运行维护、订单技术排查入口 |

一批采集可匹配多笔订单，但一条流水最终只绑定一笔订单，不合单、不拆单。数据库只保留最终匹配的流水；未匹配收款应查来源平台账单及接收日志，没有后台补匹配队列。

日常处理优先从“交易订单 → 详情”进入这些记录。只有需要跨订单排查时，再打开独立的流水、商户通知或回调日志列表。

监听收款成功后可查看最终匹配流水；易支付平台订单通过平台回调确认，可以没有到账流水，应查看平台订单号和处理记录。人工确认的依据保存在处理记录中。通道回调日志按通道查询时可能包含其他订单；没有关联流水时，继续查看处理结果和请求编号。开发者的批次与记录关联规则见[支付数据约定](V1-22-支付链路与数据约定.md)。

## 金额、日期和编号

业务金额是网站下单金额，提示金额用于付款识别，实收金额来自确认依据。对外通知 `money` 使用原业务金额，不因偏移而变成更大的值。

页面时间按上海时区。工作台成功金额按付款日期汇总，创建数/成功率按创建日期口径统计，帮助按钮中有具体解释。

业务号 B、支付号 P、通知号 N 和退款号 R 均为 20 位：一位前缀＋14 位创建时间＋5 位随机数，例如 `P2026100915304505189`。同秒内不承诺编号严格递增，按创建时间和内部 ID 排序；数据库唯一键负责最终防重复。

订单详情的“处理记录 → 技术信息”显示原单的支付产品（pay_product）及支付动作（pay_action），用于核对插件实际采用的付款准备路径。页面读取保存时的标识，不按当前通道配置推测；尚未准备材料时显示“—”。
