# 微信手机与 PC 监听

这套方案把微信收款消息转发给 MPAY，用来确认原订单是否到账。安卓手机用户按本页“安卓 SmsForwarder 配置”操作；PC 方案另有工具和消息格式要求，不是安装普通电脑版微信就能直接使用。

插件编码为 `wxpay_receipt`，支付方式为 `wxpay`，日常通过后台选择名称即可，不需要手填这些编码。

## 准备与通道参数

准备本人有权使用的微信收款码、能持续收到到账消息的设备，以及可从设备访问的 HTTPS 站点。先按[新增通道](V1-06-收款通道与支付方式.md)创建微信通道。

收款材料、金额/备注模式、有效期和偏移含义见[插件配置约定](V1-07-插件管理与配置约定.md)。再填写：

| 字段 | 怎么填 |
| --- | --- |
| 通知密钥 | 自行生成的专属随机值，16～1024 字符；MPAY 与工具保持一致，不使用应用 KEY 或管理员密码 |
| 通知时间容差 | 默认 300 秒，范围 30～3600；优先同步时间与改善网络，不靠无限放宽解决失效 |

保存并启用后，在通道详情取得通知地址。示例：`https://pay.example.com/api/pay/13/notify`，其中 `13` 是**通道 ID**，不是插件配置 ID、PID 或订单号。

## 安卓 SmsForwarder 配置

工具应安装在实际接收微信收款通知的手机上，允许通知读取、自启动及后台运行。具体权限页面依手机系统而异。

先在 MPAY 新建微信通道，选择“微信手机/PC 收款监听”。没有确认通知内容包含备注时保持“按金额识别”，收款材料使用自己的微信收款码；通知密钥按[生成说明](V1-07-插件管理与配置约定.md#生成手机通知密钥)准备后复制。保存后按[通道通知地址说明](V1-06-收款通道与支付方式.md#保存后复制通道通知地址)复制通知地址。

从 [SmsForwarder 官方项目](https://github.com/pppscn/SmsForwarder)进入其发布页获取工具，记录实际安装版本。下面按字段名称说明，具体界面随版本变化；不要从聊天附件或不明下载站获取代填密钥的工具。

| 在手机工具中找到 | 设置成什么 |
| --- | --- |
| 发送通道类型 | Webhook |
| 请求方式 | POST |
| Server / WebServer | 当前微信通道的完整 HTTPS 通知地址 |
| Secret | 与 MPAY 当前微信通道相同的通知密钥 |
| webParams / 请求参数 | 留空，使用工具的默认表单 |
| 成功响应关键字（若有） | 小写 `success` |
| 转发规则类型 | 应用通知，来源限制为微信 |
| 规则的自定义消息模板 | 复制下方完整 JSON 一行 |

1. 在“发送通道”新增 Webhook，选择 POST。
2. Server 填通道详情提供的完整 HTTPS 地址，Secret 填同一通知密钥。
3. 本版 MPAY 的成功正文是 **`success`**，不要照搬旧版教程中的 `200` 正文关键字。
4. 新增“应用通知”转发规则，选择微信对应 Webhook，开启自定义模板：

```json
{"title":"{{TITLE}}","msg":"{{MSG}}"}
```

上面是写入 `content` 的模板，**不是整条 HTTP JSON 请求体**。工具最终应发送 `application/x-www-form-urlencoded` 的四字段表单，详见下节。

容易混淆的地方是 Webhook 的请求参数和规则的消息模板。对于遵循官方默认行为的 SmsForwarder，Webhook 使用 POST、填写 Server 和 Secret，`webParams` 留空，让工具生成默认表单；上面的 JSON 放到应用通知规则的自定义消息模板。把它填进 webParams 会切换为 JSON 请求，与当前 MPAY 接口不符。字段行为以 [SmsForwarder 官方 Webhook 说明](https://github.com/pppscn/SmsForwarder/wiki/附录1：向webhook发送post-get-put-patch请求)为依据。

采用 V2 教程中的中文多重匹配规则时，填写：

```text
并且 是 APP包名 相等 com.tencent.mm
并且 是 通知标题 相等 微信支付
 或者 是 通知标题 相等 微信收款助手
 或者 是 通知标题 相等 微信收款商业版
```

“或者”前保留一个半角空格。这只适用于支持该规则语法及上述 Webhook 合同的客户端版本；如果版本界面不同，按相同的包名和标题条件配置，不取消来源限制。模板变量的引号、换行须由工具正确转义，最终 `content` 必须是合法 JSON。

实际解析接受上述三个标题，正文应有“到账/收款/收款到账＋金额”等收款信息；备注模式还需消息携带四位付款备注。没有确认来源包含付款备注时，先使用金额模式。

保存规则后，确认规则和发送通道都已开启。锁屏一段时间后再做一笔核对，确保后台权限没有被系统关闭；具体手机权限页面及 PC 工具界面须按你的版本操作，本页不把其他版本截图当成通用步骤。

## 开发参考：通知传输格式

使用上面的兼容工具时，下面四个字段及签名由工具生成，普通用户无需手工计算。自行开发转发器时才需要阅读本节。

| 字段 | 值 |
| --- | --- |
| `from` | 手机为 `com.tencent.mm` |
| `content` | 包含 `title`、`msg` 的 JSON 字符串 |
| `timestamp` | 当前发送时间的 13 位毫秒时间戳字符串 |
| `sign` | 工具生成的 Base64 HMAC-SHA256 签名 |

签名原文为 `timestamp + "\n" + secret`，HMAC 密钥也是 `secret`。只接受 POST 表单和这四个字段，通知 URL 不附查询参数。HTTPS、时间容差、发送方及消息模板都要通过校验。

该兼容签名不覆盖 `from/content` 正文，也不是微信官方交易签名；不要向不可信转发端泄露通知密钥。收到 `success` 后仍在 MPAY 原订单确认支付与商户通知状态。

## PC / wxtool

仅使用安卓手机时可跳过本节。当前资料尚未提供经过实际验证的 PC 工具版本及逐屏配置教程，下列内容是接入格式要求，需要由工具维护者核对后接入。

需要能够输出 `wxtool.officialAccount.message` 事件并按相同四字段合同投递的工具。这里描述当前接收合同，不表示任意 wxtool 版本均已验证。

- 通知来源只接受 `gh_3dfda90e39d6` 与 `gh_f0a92aa7146c` 两个已适配公众号。
- `content` 保留完整事件对象：`event`、`account.username`、`message` 和 `delivery.messageKey`。
- 消息须为 `incoming`，`source=message`，不能为 fallback；保留原始 XML、秒级 `createTime`、`sortSeq`、`localId`。
- `delivery.messageKey` 采用工具实际游标：`账号数字ID:公众号:sortSeq:createTime:localId`，不得自行换成随机字符串。
- 插件支持当前声明的赞赏、普通收款和店员消息模板，并交叉核对标题与收款金额；系统“备注”文字不等于付款人备注。

请在工具中订阅实际收款公众号，设置正确通道地址和通知密钥，保留原始结构投递。具体微信版本、工具版本及 XML 模板需按实际样本核验；缺少适配时不得通过伪造字段绕过校验。

## 验证与排查

按[第一笔收款](V1-04-完成第一笔收款.md)先建立待付订单，再付款并检查设备投递日志、通道回调日志、原订单及商户通知。发送工具的普通测试消息不等于有效到账。

| 现象 | 检查 |
| --- | --- |
| 完全没有转发 | 微信通知开关、通知读取权限、规则启用、手机后台或 PC 休眠 |
| 验签或时间失败 | 当前通道密钥、时间同步、表单编码、签名中的 `+` 是否被误转为空格 |
| 请求格式失败 | 是否发成 JSON POST、是否有额外字段、通知地址是否附查询参数 |
| 未匹配订单 | 支付方式、提示金额/备注、原单有效窗口及来源通道 |
| MPAY 成功，商城未更新 | 转到[商户通知排障](V1-17-通知验签与联调排障.md)，不要重复付款 |
