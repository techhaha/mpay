# 开发环境与目录结构

使用 PHP 8.2 及以上、MySQL 5.7.9 及以上和锁定 Composer 依赖。正式部署不依赖 Node、前端构建服务、Redis 或 Workerman。

## 本地启动

在源码根目录执行 `composer install`，保留锁文件，再按网页安装配置专用开发库。仅本机开发可使用：

```sh
php -S 127.0.0.1:8000 -t public public/router.php
```

PHP 内置服务器不作为生产 Web 服务器。PHP 路径可以使用本机实际 8.2+ 可执行文件，不强制固定小版本。实际平台调用与合成测试应使用不同数据和明确的配置。

## 目录职责

| 目录 | 放什么 |
| --- | --- |
| `app/http` | 页面/协议控制器、入口验证器及入口中间件 |
| `app/route`、`route` | 按安装、后台、协议和收银台组织的显式路由 |
| `app/service/payment/epay` | 易支付认证、参数与协议响应 |
| `app/service/payment/order` | 建单、支付尝试、生命周期、退款编排 |
| `app/service/payment/routing`、`config` | 选路、默认关联与通道配置 |
| `app/service/payment/plugin` | 插件发现、实例装配、动作派发和标准结果检查 |
| `app/service/payment/receipt` | 回调、证据检查和到账流程 |
| `app/service/payment/collection` | 主动采集、窗口、会话和游标协调 |
| `app/service/payment/notify`、`runtime` | 商户通知与原生工作者运行 |
| `app/common/payment` | 四个独立插件主类，一类一个插件，直接实现接口 |
| `app/common/interface`、`sdk` | 实际使用的接口；平台 HTTP/签名/解析 SDK |
| `app/repository`、`app/model` | ORM 查询/锁/持久化；表映射、类型和关联 |
| `app/common/base`、`constant`、`util` | 公共服务基础、状态常量、金额/编号/日志等共性能力 |
| `database/migrations` | 版本迁移、建表 SQL 及字段注释 |
| `view`、`public/assets` | ThinkPHP 模板、本地 Layui、公共请求与页面 JS、品牌素材 |
| `tests` | 隔离单元/集成用例；专项平台诊断仅在 `tests/diagnostics` |
| `runtime` | 日志、会话、缓存和本机验证证据，不作为源码发布 |

## 分层约定

Controller 负责入口与响应；继承 `think\Validate` 的验证器检查不可信字段；Service 编排业务不变量；Repository 只查询、加锁和持久化；Model 不通过事件隐藏支付副作用。

仓储直接使用注入模型的 ORM 链，`requireTransaction()` 只是事务前提检查，不开启另一层事务。Service 使用 `BaseService::transaction()`；只有可安全重放的数据库闭包才使用 `transactionRetry()`。外部 HTTP 不进入数据库重试事务。

`AppService.php` 是应用装配入口，用于具有特殊构造的容器绑定，不改 vendor。插件专属字段和账号解释留在插件，SDK 不决定业务订单成功。

## 检查与测试

```sh
php -l app/common/payment/YourPayment.php
php tests/run.php --list
php tests/run.php
```

只有开发源码包提供测试目录；发行包若排除测试，回到对应源码执行。集成测试需显式提供私有 `MPAY_TEST_CONFIG`，使用允许创建/删除隔离库的专用测试账号，再执行 `php tests/run.php --integration`；不能指向业务 `.env`。`--list` 只列出用例，不代表通过。

修改类时同步职责、数组形状、金额单位、事务/锁/幂等与异常注释。常规 getter 不机械重复类型；不承诺实现中没有的验签或恢复能力。
