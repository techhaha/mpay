# 主动采集与会话协作

仅实现 `ReceiptCollectorInterface` 的插件由 watch 调度。主动采集位于 `app/service/payment/collection`；SDK 不依赖订单表，平台字段由插件解释。

## 三种身份与凭证摘要

插件初始化后返回四个字段，身份摘要包含插件编码，使用 SHA-256：

| 字段 | 用途 |
| --- | --- |
| `account_key` | 归并实际收款范围、流水幂等和识别金额占用 |
| `query_key` | 划分需要查询的商户、门店或终端范围 |
| `session_key` | 划分登录会话；无登录会话的签名 API 返回 null |
| `auth_fingerprint` | 识别同登录身份凭证是否冲突，不作为账号身份 |

密码不进入身份键；字段选择由具体插件定义，公共服务不按用户名等猜测。每通道配置仍独立保存，共享的是查询协调与会话，不是可编辑的配置对象。

收钱吧同登录身份复用会话，不同门店的切换和查询互斥；同查询范围合并为一次整窗任务。支付宝账单使用签名请求，session_key 为 null。

## 分页合同

```php
public function collectPage(array $window, ?array $pageToken, ?array $session): array;
```

`$window` 包含 Unix 秒级 `from`、`to`（左闭右开）和 `DateTimeImmutable deadline`。续页参数由上一次返回提供，不能在页失败时跳过；session 是同登录身份的共享会话。

```php
return [
    'records' => $normalizedRecords,
    'complete' => $lastPage,
    'next_page' => $lastPage ? null : $nextPageToken,
    'session' => $updatedSession,
];
```

只有完整、有界窗口取齐后，服务才一次性将批次交给插件匹配；分页失败不提交部分批次，也不推进完成水位。未匹配记录不持久保存。事件/交易号稳定，重叠窗口重读不会换绑已消费流水。

## 任务与网络边界

1. 在短事务中认领查询与需要的会话租约，冻结配置 ID/版本集合。
2. 事务外访问平台，受页数、事件数和 deadline 限制。
3. 结果提交前复核身份、配置版本、租约 token 与期限。
4. 匹配成功逐笔进入生命周期；完成后更新水位与会话。

过期进程结果不能覆盖新持有者。相同登录使用冲突凭证时延后并记录问题，不交替重试两个密码。仅停用且没有未结订单的配置退出相关采集集合，不能为了省请求抛弃原单责任。

## 开发边界

修改二维码或付款有效期不应无理由清空登录会话。真正凭证变化需要按会话合同更新；查询范围变化不能覆盖原在途订单使用的快照。

日常只运行 watch/work；平台专项诊断位于开发目录 `tests/diagnostics`，由开发者明确发起，不能注册成每平台一个生产命令。任何真实平台网络诊断都不应伪装成只读本地检查。
