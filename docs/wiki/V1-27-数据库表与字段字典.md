# 数据库表与字段字典

本字典于 2026-10-14 按纯净安装基线的实际空库结果核对，共 26 张表、296 个字段（包含安装进度表）。MySQL 5.7 的整数显示宽度不代表业务编号长度，金额为整数分，时间使用 Asia/Shanghai。

当前唯一新装基线为 `202610140100_install`，直接定义最终字段、索引、外键及注释，不执行历史升级链。识别金额/备注使用通道内有效订单的 JSON 快照；登录态存插件私有文件缓存。新装执行器保留步骤摘要和中断进度，不自动清空、回填或接管旧开发数据库。凭证仅在已认证管理员的受控编辑接口返回，不进入列表和日志。

## 交易约束与查询索引

- ma_receipt_scope 的 api_config_id/pay_type_id 唯一，表示配置与支付方式的归属范围，不是平台账号，也不是金额/备注分配范围。
- ma_receipt_flow 的 plugin_code/event_key 与 plugin_code/platform_trade_no 分别唯一，最终事实不能跨通道换绑。
- ma_pay_order 的 plugin_code/channel_trade_no 唯一，阻止同一平台收款被人工和采集重复确认给不同订单；平台号尚未取得时为 NULL。
- ma_pay_order 的 idx_pay_collection 按 plugin_code/status/expire_at/id 支持待核对订单扫描。
- ma_pay_order 的 idx_pay_channel_active(channel_id,status,expire_at,id) 支持通道内有效待付订单查询，idx_pay_channel_receipt(channel_id,pay_amount,expire_at,id) 支持按通道与金额定位候选。
- ma_receipt_flow 的 idx_receipt_paid(paid_at,pay_no) 支持付款日期范围统计，再按支付单核对应用归属。

识别金额/备注唯一性由插件在通道行锁内读取有效订单快照并分配，不另建预约表。ext_json 保留插件准备及展示快照；JSON 读取先用订单号或普通索引限定范围，不新增整份 payload 附表。实收统计可能需要读取日期范围内的多行流水，索引不意味着任意数据量下都是常数时间。

采集永久状态位于 runtime/receipt，文件内容由插件解释，不承担交易幂等。通知任务及其执行租约继续保存于数据库。MySQL DDL 不作为可回滚业务事务，迁移保留进度和中断续跑。
