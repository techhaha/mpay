# 收银台页面与扩展

收银台展示本次订单的付款要求，并查询本地交易结果。页面不确认到账、不重算识别金额，也不自行发送商户通知。

## 付款与完成流程

首次打开收银台时，仅尚未执行的订单自动调用一次 POST /api/cashier/prepare；选择支付方式通过 POST /api/cashier/select 发起。已有付款材料直接复用。中断执行在原执行期限到达后提供准备按钮，由普通付款请求触发恢复，派发与生命周期继续核对原单、期限和执行 token，复用原识别事实及付款窗口，不再按重放能力标志判断；状态轮询和 payment:work 均不代替用户发起准备。没有再次访问的未准备订单等待到期。

付款页只显示一处“应付金额”。金额识别订单使用本单识别金额；原金额和偏移仍保留在后台及订单记录。备注模式同时展示付款备注。订单信息可展开查看。

内置扫码监听插件的普通扫码及手动备注共用二维码布局，支付标识按本单支付方式显示。金额模式在二维码下方显示付款提示和剩余时间；备注模式将提示替换为“付款备注（必填）”、本单备注码及复制按钮。付款区域只给二维码加细边框，上传的收款图保持原比例完整显示，不裁切成正方形；窄屏下付款要求和倒计时可上下排列。订单详情与刷新操作统一位于底部，正常付款时不重复显示整块状态提示。

epay V1 默认 submit 页面支付，插件生成指向第三方 submit.php 的签名链接，由浏览器 GET 进入平台收银台。可选 mapi 下单时，其 qrcode 复用二维码组件。submit 链接及 mapi 的 payurl/urlscheme 都使用 `cashier-jump.js` 注册的 `jump` 页面：网页链接首次自动前往，客户端协议由用户点击“前往支付”唤起，并保留剩余时间。回到本站后继续查询原单，不根据回跳参数确认成功，不新增轮询循环；具体导航约定见下方展示注册说明。示例参数为 `presentation={pay_page:'jump',pay_params:{url:'https://pay.example.com/order/...'}}`，唤起协议仅支持 alipay/alipays/weixin。

付款超时、订单关闭和明确支付失败时，页面隐藏二维码及应付金额，分别显示“付款时间已结束”“订单已关闭”“支付未完成”，保留订单详情和“检查支付结果”。超时提示同时参考服务端的付款期限标志，避免交易状态尚未更新时仍提示等待付款；页面不因此改写交易状态或认定没有到账。已支付优先显示商户确认状态，关闭和失败不被期限提示覆盖。停止付款后仍查询原单，后续确认到账可进入商户确认流程。

收款后立即撤下二维码及付款操作，进入商户确认阶段。有通知地址的订单须取得 HTTP 2xx 与纯文本小写 `success` 应答，并成功记录 `first_ack_at`，才允许完成导航。有返回地址时立即自动回跳；无返回地址时进入默认成功页。无通知地址的后台通道测试订单直接进入默认成功页，不虚构商户确认。

错误正文、网络超时、任务已发送和通知任务缺失都不能当作确认。首次有效 ACK 不因后续补发失败撤销；人工暂缓或停止重试会提示联系商户。浏览器本轮最多等待 60 秒，超时后可“重新检查通知”；此操作只查询，不补发、不重下单。后台重试不依赖付款页面保持打开。

商户确认等待、暂缓及停止重试均在统一状态区展示，保留“已支付”的付款事实。等待超时只表示本轮自动检查结束，不表示付款失败或商户最终拒绝；没有有效确认时不会自动跳转。

## 读取接口职责

以下是收银台同源接口，均须携带本单 `biz_no` 和随机 `token`，不替代易支付商户接口：

| 接口 | 调用与数据 |
| --- | --- |
| GET /api/cashier/order | 首屏或展示状态变化时读取完整公开详情；金额只有 `amount`，没有原金额、偏移额或商户通知详情 |
| GET /api/cashier/status | 待付款约每 3 秒查询；只读业务单、支付单必要字段，不查通知表、品牌、路由或完整扩展 JSON |
| GET /api/cashier/completion | 支付成功后约每 2 秒查询；业务单负责凭证/归属校验，通知摘要负责首次 ACK 和调度状态 |
| GET /cashier/return | 导航时重新检查成功与商户确认，再按原订单凭证和冻结目标签名回跳 |
| GET /cashier/success | 无返回地址且满足完成条件才显示默认成功页；不允许直接访问绕过确认 |

默认成功页由 `CashierService::successPage` 在一个只读一致性事务中核验订单凭证、双单关联与成功状态、原金额以及所需商户首次 ACK，请求读取额度只计一次。模板只接收商品名、实收金额、支付单号和隔离环境提示；不再先调用 completion 再调用完整 view，不组装付款材料、不查询品牌或路由。订单仍复用现有读取及金额证据核验，不新增查询模型。完成查询与成功页共用完成条件判定；签名回跳入口仍独立核验凭证、付款事实和商户确认。

`status.revision` 是展示相关状态的摘要，不是新的数据库列。不仅支付状态变化，当前支付单、付款材料就绪或可恢复执行状态变化，也会触发详情刷新。首次打开就已支付的订单直接进入确认阶段。隐藏页面暂停轮询，恢复时查询原单；迟到响应不会覆盖新写操作或重新检查的结果。

隐藏期间不延长本轮 60 秒商户确认等待。恢复可见时，即使等待已超时或页面已提示暂缓/停止重试，也补查一次 completion；复用现有请求队列和限流等待，不另开轮询。已满足完成条件才导航；仍未确认时保留“重新检查通知”，不自动重启 60 秒等待、不补发通知、不重新下单。用户主动点击“重新检查通知”才开始新的等待轮次。

`completion.action` 为 `payment`、`wait`、`attention`、`return` 或 `success`。`required=false` 表示没有通知义务，不等于 `confirmed=true`。仅完成时返回本站相对地址 `next_url`，前端按动作展示并直接跳转，不再复核 URL 的协议、路径和凭证。目标页面入口仍核对订单访问凭证、付款事实及商户确认，不接受外部传入的成功标志或任意返回地址。上述状态为读取结果，不新增冗余订单通知字段。

二维码图片由资产服务或插件提供公开地址，展示组件处理加载失败，不再要求 URL 属于固定的 `/storage/` 目录。支付宝付款链接由插件生成，组件只保留 HTTP(S) 网页协议检查，不另维护平台域名和路径白名单。

浏览器最终返回商户时使用订单冻结的 return_url：下单检查格式与可选应用域名，成功回跳使用原凭证签名，不执行服务器出站端口/IP 限制或 DNS 查询。商户通知仍由服务器发送，继续执行自己的网络目标检查。

## 支付展示快照与注册

银行卡转账注册为 page/bankTransfer，由 cashier-bank-transfer.js 展示 bank_name、account_name、card_number，使用公共金额区和 expires_at/server_time；户名、卡号及应付金额通过已有剪贴板工具复制，不独立查询或判断到账。到期、关闭与成功时由公共流程撤下转账资料。当前页不生成银行卡转账二维码或银行 App 链接，具体收款及消息约定见[银行卡公众号收款](V1-33-银行卡公众号收款.md)。

插件返回 `presentation.pay_page` 与 `presentation.pay_params`，并在标准动作结果中声明 `pay_type/pay_product/pay_action`。插件负责平台链接的生成、平台参数检查和公开材料选择；派发服务经过通用结果检查后，由生命周期在原执行 token 与事务保护下保存 `ext_json.presentation`。

通用检查位于 `PaymentPluginPayResultValidator`：核对标准结构与标识，保留插件自定义嵌套参数，不包含平台域名、二维码、备注等字段算法，也不把对象、资源或不可编码内容保存为页面参数。

产品和动作标识保留在原单快照，后台订单技术信息可查看；具体值由插件执行分支决定，核心不猜测或维护平台产品枚举。前端组件仍由 pay_page/_page 选择，两个追踪标识不决定交易成功。当前插件的对应关系见[产品与动作说明](V1-23-支付插件开发.md#5-当前静态码结果)。

### 动态链接收款码

`cashier-receipt.js` 同时注册 `page/dynamicReceipt`。适用于平台已经生成固定金额付款链接的收款方式，共用现有二维码生成、品牌、倒计时和订单状态查询，不独立建单或确认收款。

```php
'presentation' => [
    'pay_page' => 'page',
    'pay_params' => [
        '_page' => 'dynamicReceipt',
        'payment_url' => 'https://pay.example.com/order/...',
    ],
],
```

`payment_url` 是唯一公开付款链接，同一原值用于二维码、打开和复制；不同时再传 qrcode_content、图片地址、设备类型或重复的到期字段。链接为绝对 HTTP(S) 地址，UTF-8 最多 2331 字节，与现有二维码编码上限一致；不得截断付款链接，也不得携带后台登录凭证。平台链接生成和平台参数检查仍由插件负责。

| 当前浏览器 | 展示与操作 |
| --- | --- |
| 微信内，且原单为微信支付 | 同页签首次自动前往链接，并保留付款按钮和二维码 |
| 支付宝内，且原单为支付宝支付 | 同页签首次自动前往链接，并保留付款按钮和二维码 |
| PC 浏览器 | 展示对应支付应用的扫码指引及复制链接 |
| 普通手机浏览器 | 展示二维码、复制链接和打开付款页面按钮 |
| 微信/支付宝环境与原单方式不匹配 | 保留二维码和复制指引，不自动前往或展示打开按钮 |
| 云闪付及其他未识别的付款应用 | 使用二维码及链接备用方式，不自动构造 App 唤起协议 |

当前浏览器的识别只控制展示，不使用建单时冻结的设备信息强制决定后续打开方式，也不更改原订单的支付方式。组件复用网页跳转的同页签原单标记；返回、刷新和重新挂载不再自动前往。存储不可用时保留人工打开入口；复制失败时显示可选中的只读链接，不提示复制成功。过期、销毁或已进入付款结果阶段后停止操作并清理事件和跳转计时器。

第三方是否可以支付后自动回到本站，取决于其平台接口；本组件不补造返回参数或根据页面跳转判断支付成功。用户返回原页后，仍由公共收银台查询及原商户确认流程决定完成导航。通用组件随基础版本提供，插件通过已有展示注册名使用，不加载远程脚本或模板。

### 展示字段约束

| 字段位置 | 必填条件 | 类型与限制 |
| --- | --- | --- |
| 动作结果 `pay_type` | pending 必填 | 1～32 个 ASCII 字符，小写字母开头，后续只能是小写字母、数字或下划线；与本单支付方式一致 |
| 动作结果 `pay_product`、`pay_action` | pending 均必填 | 各为 1～64 个 ASCII 字符，字母开头，后续只能是字母、数字或下划线，例如 `alipay_qrcode`、`display_qrcode` |
| `presentation.pay_page` | pending 必填 | 与上述产品/动作标识使用相同的 1～64 字符语法；当前组件使用 `page` 或 `jump` |
| `presentation.pay_params` | pending 必填 | PHP 关联数组，允许空数组 `[]`，不接受非空连续索引列表；内部值为可编码的纯 JSON，不含 PHP 对象或资源 |
| `presentation.pay_params._page` | pay_page 为 `page` 时必填 | 同样为字母开头的 1～64 个 ASCII 字符标识；必须与前端注册名称一致，例如 `receiptQrcode` |

标识区分大小写，不能填路径、URL、中文或含连字符的名称。`pay_params` 使用 `JSON_UNESCAPED_UNICODE` 编码后最多 65536 字节（64 KiB），JSON 编码深度上限 32；这不是字符数或单字段上限。空数组虽通过通用容器检查，`page` 模式仍因缺少 `_page` 而不合法。每种组件另有自己的必需参数和材料限制。

插件返回的 `presentation` 只包含 `pay_page/pay_params`，不要把 `pay_type/pay_product/pay_action` 重复嵌入其中。服务检查后才把这三个标准标识合入保存的展示快照。各动作完整返回示例见[支付插件开发](V1-23-支付插件开发.md#5-当前静态码结果)。

`pay_params` 是插件主动声明的公开数据，不能包含密钥、整个配置、整个订单扩展或上游原始响应。服务只公开标准展示快照，不会依据字段名猜测敏感内容，也不按具体页面删减插件自定义字段。插件作者必须在返回前明确挑选材料。

收银台按权限定位当前订单后读取快照，不调用插件重新生成链接。公共响应统一提供 `amount`、`expires_at` 和 `server_time`（Unix 秒）；每次读取重新提供服务器时间，付款期限来自本单已保存事实。页面材料里不重复注入时间或二维码编码规格。

- 前端入口：`cashier-pages.js` 的 `MpayCashierPages.register(payPage, name, mount)`；page 的 name 与 `_page` 精确对应，直接模式 name 为空。
- `mount(host, order, params, context)` 只操作自己的展示区域，可返回 `tick()` 和 `destroy()`。公共流程驱动 tick，销毁时释放监听和资源。
- `context.error()` 报告展示失败，`context.expired()` 请求刷新原单；组件不能独立轮询、确认到账或重发支付。
- 未注册组件显示明确错误，不执行任意 HTML、脚本、文件路径或远程模板。
- 公共区域只显示 `order.amount`，组件不再显示第二组金额或自行计算差额。链接实际使用和文本插入由组件检查协议、目标和转义。

`jump` 付款区将主提示、辅助说明、付款按钮与剩余时间居中排列，主按钮复用 Layui，并用公共主题色和间距区分主次。金额仍由公共区域单独显示，订单详情与刷新操作保留在底部辅助区；窄屏按钮不超过可用宽度。

HTTP(S) 付款链接在首次展示时自动前往；以支付单号在当前页签的 sessionStorage 记录一次导航，付款返回、刷新或重新挂载时不重复自动跳走，继续由公共流程查询原订单。用户仍可点击按钮前往；sessionStorage 不可用时只保留按钮，避免循环导航。支付宝/微信客户端协议由用户点击唤起，不自动调用。展示模块销毁时取消尚未执行的导航，已过期材料不自动前往；这些处理不确认到账，也不改变公共成功导航和金额核验。

该标记只控制已经回到本站后的自动导航，不修改浏览器历史，也不保证工具栏后退固定回到收银台；第三方返回本站使用本单的 return_url。

当前 `pay_page=page` 的内置组件如下；直接跳转另用 `pay_page=jump`：

| 组件 | 插件返回参数 | 页面职责 |
| --- | --- | --- |
| receiptQrcode | _page、qrcode_content、qrcode_image_url、instruction、remark | 有图片则显示插件提供的公开图片地址，否则生成二维码；展示扫码或手动备注指引 |
| alipayTransfer | _page、qrcode_content、transfer_url | 使用插件生成的二维码内容和手机链接，提供支付宝付款入口；不拼装金额、收款账号或 memo |
| bankTransfer | _page、bank_name、account_name、card_number | 展示银行卡转账资料；金额与倒计时使用公共字段，复制复用已有工具 |
| dynamicReceipt | _page、payment_url | 同一付款链接用于二维码、打开与复制；共用订单查询和倒计时 |

receiptQrcode 的 instruction 为 scan（默认，remark 为 null）或 manual_remark（remark 为非空文本，最多 256 字节）。生成二维码使用前端固定 Byte/M 规格，内容最多 2331 字节，最终渲染为 img，保留长按/保存能力；上传图片保持原比例。所有内置插件在 schema 中限制材料长度并检查配置，页面也检查实际展示约束。

alipayTransfer 的平台地址由支付宝账单插件生成，手机按钮组件只使用约定的支付宝 HTTPS 入口。组件消费材料并显示自动填写指引，链接打开不能证明到账。客户端自动填写能力需按真实支付宝版本验证。

## 新页面的接入步骤

1. 定义公开参数合同，明确长度、URL/客户端限制和字段用途，在插件内生成并检查具体材料。
2. 插件返回标准 pay_page/pay_params；复用现有派发、结果校验与快照保存，不新增后端专用展示类。
3. 实现并注册前端组件，在模板加载对应静态资源；复用公共金额、时间、查询和商户确认流程。
4. 验证材料保存后原样恢复、重复读取不调用插件，以及未知组件、错误材料、过期、销毁、输出转义和链接使用，再更新插件文档。

qrcode、jump、urlscheme、jsapi 等可以按相同边界扩展，但必须交付相应前端组件及使用约束；当前未交付的组件不会被回退成二维码或执行为任意脚本。

更新展示组件时同步静态资源版本；旧订单继续读取已保存材料，交易状态、原付款窗口、商户通知与访问权限由公共流程处理。
