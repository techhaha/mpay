# 动态码收款插件（可选安装）

五款平台插件按需另行安装，使用明文 PHP 入口与共享 MPAY Premium 原生 SDK。使用插件前，须将网站与监听进程切换至 **PHP 8.4+**，并安装、启用与该 PHP 环境匹配的 **mpay_premium.so 扩展**。V1 基础版继续使用 PHP 8.2+，提供图鉴、国密 SDK 和收银台公共支持；内部源码开发同样要求 PHP 8.4+。这五个插件使用平台动态收款码，付款人无须输入金额或备注。不提供金额偏移、手工备注或代理选项。

| 插件 | 编码 | 需要图鉴 | 加密协议 |
| --- | --- | --- | --- |
| 天阙 Pretran 码牌 | `tianque_pretran_receipt` | 否 | AES |
| 拉卡拉缴费易 | `lakala_jfy_receipt` | 是 | SM4 |
| 星驿付驿汇客 | `xingyifu_yhk_receipt` | 是 | DES、SM2、SM4、MD5 |
| 付呗收款单 | `fubei_cashier_receipt` | 否 | MD5 |
| 易宝易缴费 | `yeepay_boss_cashier_receipt` | 是 | SM2 |

国密统一使用 V1 基础版附带的本地 SDK，固定 lpilp/splsm2 2.0.1，不由根 Composer 管理，没有 suggest 或第二套算法库。SM2 在星驿付认证时加密 SM4 会话密钥、在易宝登录时加密密码，这两款插件需要网站与监听所用 PHP 启用 GMP。SM4 优先使用 OpenSSL，不支持时使用同一 SDK；拉卡拉只使用 SM4，不额外强制 GMP。基础版安装和全局环境诊断不以 GMP 阻止使用。

## 安装与开始使用

1. 核对 V1 基础版本已经包含通用 `page/dynamicReceipt` 展示、“系统设置 → 验证码识别”、公共图鉴 SDK 及国密 SDK。基础依赖沿用原 V1 的 vendor，不为安装付费插件执行 Composer，也不覆盖整套 vendor。需要图鉴的插件在此填写图鉴账号、密码并保存；不需要图鉴的插件无需配置图鉴。
2. 将网站与监听进程切换至 PHP 8.4+，按下节说明安装、启用匹配的 `mpay_premium.so` 扩展包，再按文件清单复制所购插件的一个 PHP 入口。旧明文平台 SDK 已退役，不作缺扩展回退。图鉴、国密及收银台支持已经由基础版提供，不用覆盖公共文件。不要删除其他已安装插件使用的共用文件。
3. 星驿付、易宝先准备 GMP：在宝塔对应 PHP 版本的“安装扩展”中安装并启用 gmp；网站与监听可能使用不同配置，两者都要确认。Ubuntu/Debian 安装失败且提示缺少 GMP 库或头文件时，到宝塔左侧“终端”执行 `sudo apt-get install libgmp-dev`，再回 PHP 扩展页面重新安装 GMP。该命令补齐开发包，不等于 PHP 扩展已经安装；其他报错按实际日志处理。
4. 在“插件管理”刷新列表并启用插件，再新增通道。填写 V1/V2 通用授权码、该平台的登录账号、密码和收款范围；通道表单只显示当前插件声明的字段。GMP 要求及失败处理由两款插件自身 description 声明，公共表单不追加平台专属说明。
5. 更新插件文件后，重启原 `payment:watch` 和 `payment:work`，使常驻进程装载新代码；修改扩展配置时同时重启对应 PHP 服务。不新增守护入口。
6. 在“运行维护”按收款通道筛选并查看采集状态，等待首次预登录和验证查询成功，再从通道测试入口发起付款。

平台账号的实际权限决定可用支付方式。插件声明支付宝、微信和云闪付，并不代表平台已为该账号全部开通。

### 安装 MPAY Premium 扩展

当前 API 3 源码仍在修改阶段，匹配的扩展包尚未构建。以下步骤面向后续配套发布包，不表示现有 API 2 二进制可以直接使用。

当前交付目标为 **Linux x86-64 / PHP 8.4 NTS 非调试版 / Zend Module API 20240924**，已在 Ubuntu 22.04、PHP 8.4.26/8.4.27 核对。PHP 8.2/8.3 无法加载本包；PHP 8.5、ZTS、ARM64、Windows 和 Alpine musl 均不能复用此包，尚未提供对应构建。免费基础版不会因此提高最低版本。

扩展包包含 `mpay_premium.so`、`lib/libphpx.so`、构建资料、SHA256SUMS、许可和 NOTICE。两份 `.so` 必须保持同包及相对位置，不能只取其中一份。系统运行库需要 libstdc++、libgmp 和 libmpfr；这是共享库依赖，区别于仅星驿付/易宝 SM2 需要的 **PHP gmp 扩展**。不要从其他 PHP 或其他发行版随意复制运行库。

1. 在宝塔确认网站与原 watch/work 都使用同一 PHP 8.4 NTS。通过该版本的 `php -i` 核对 PHP API、Thread Safety、Debug Build 和 extension_dir，用 `php --ini` 查看 CLI 实际配置。不要只检查系统默认 `php`。
2. 验证交付目录中的 `sha256sum -c SHA256SUMS`。将整包放入版本独立、PHP 用户可读的目录，例如 `/opt/mpay_premium/1.2.0/php84_linux_x86_64_nts/`；保留上一个完整版本以便回滚。
3. 在对应 PHP 配置中增加一条 `extension=/opt/mpay_premium/1.2.0/php84_linux_x86_64_nts/mpay_premium.so`。**不要**再写 `extension=libphpx.so`；它是由动态链接器加载的配套库，不是 PHP 扩展。CLI 与 FPM 如使用不同 ini，需要分别配置。
4. 用该版本 CLI 的 `php --ri typephp_mpay_premium` 核对模块。该模块在 PHP 中名为 `typephp_mpay_premium`，文件名为 `mpay_premium.so`。检查 `phpversion('typephp_mpay_premium')` 为 1.2.0、SDK `API_VERSION` 为 3，并确认 cURL/OpenSSL 已启用。
5. 重启对应 PHP-FPM 与已有 watch/work，检查新 PID、错误日志和运行维护。CLI 能加载不证明 Web 已加载；需要分别确认，不增加其他守护进程。不要在 PHP 已加载时原地覆盖二进制，使用新版本目录切换配置并重启。

升级新增平台仍是更新同一个扩展包，只安装新购插件的入口即可；保持 API_VERSION=3 时旧入口继续使用原方法。升级失败时恢复上一整包的配置路径和对应入口，再重启 FPM/watch/work；回滚不改数据库、订单或登录态。卸载一款时不删除其他插件共用的扩展。

### 离线授权

五款共用原 V2 `license-tools` 的 RWLIC1 授权工具、公钥和产品标识 `receipt_watcher`，插件编码也保持一致，V1/V2 授权码通用。根据许可证中的插件范围、站点域名、到期时间和 grace_days 验证；expires_at=0 表示永久授权。使用同一个工具续签后，更新通道插件参数中的授权码即可。授权私钥仅保留在签发端，不随插件或扩展交付。

仅在 SDK 发起**新的平台收款单**之前核验授权。保存参数、init、登录、预登录、查流水、匹配、确认收款及商户通知不检查商业授权。授权失败直接拒绝本次新建，不调用平台；已生成的二维码继续复用，星驿付已取得稳定页面的后续步骤继续按原阶段处理，结果未知的变更仍禁止盲目重放。填写错误或到期不会阻断已经产生的订单核对。

插件向 SDK create 分别传入原订单 $order 和建码进度 $meta；SDK 内部读取 order.notify_url，直接使用独立的 meta。两者不合并、不相互拆取，原数据库进度保存位置和交易保护不变。当前源码目标为入口 1.3.0、扩展 1.2.0 / SDK API 3，本轮仅语法/静态检查，尚未编译；现有 1.1.0 / API 2 产物不能与当前入口混用，版本检查会明确拒绝。

本站域名取自服务生成的本地支付回调 URL，只比较规范化主机名，不区分 HTTP/HTTPS、端口及路径；不使用商户通知/回跳域名。授权码由秘密输入框保存，不作为收银台参数公开。离线验证无远程授权请求、无短期缓存；服务器校时影响到期判断，无法即时撤销已签发许可证，需通过有效期和续签管理。

扩展提高阅读和修改核心逻辑的成本，不是不可破解的硬件信任边界。掌握服务器的使用者仍可能修改二进制、伪造传入域名、替换 PHP 依赖或绕过整个平台插件；单靠离线软件无法保证绝对域名绑定或防盗用。此实现没有加入额外在线授权、机器指纹或防篡改服务。

## 配置各平台

共同字段为授权码、平台登录账号、平台登录密码和账号查询间隔。密码按原值保存，配置页使用隐藏输入框和显示图标正常编辑。查询间隔只限制实际请求频率，不表示严格定时保证；还受现有监听轮询和本轮预算影响。


| 字段 | 填写方式 |
| --- | --- |
| 授权码 `license_code` | V1/V2 通用 RWLIC1 授权码；允许先留空保存配置，新建平台收款单时才验证，最多 8192 字符 |
| 平台登录账号 `watcher_username` | 填该平台工作台登录账号，与商户号、门店号分别填写 |
| 平台登录密码 `watcher_password` | 填登录密码；密钥输入仅隐藏显示，可点击显示图标修改 |
| 账号查询间隔 `receipt_watcher_query_interval_seconds` | 天阙、拉卡拉默认 3 秒，其余三款默认 5 秒；允许 3～300 秒 |
| 收款有效期 `receipt_valid_seconds` | 天阙、星驿付、付呗、易宝默认 300 秒，允许 60～1800 秒；拉卡拉使用原订单付款期限，不提供此字段 |

### 天阙 Pretran

- 商户号或完整商户名称：单一商户可留空，存在多个商户时必须唯一定位。
- 收款终端号：可选；填写后，流水详情必须符合该终端。
- 收款有效期：默认 300 秒，允许 60～1800 秒，且不得超过原业务单剩余时间。
- 查询间隔：默认 3 秒。

插件创建带固定金额和内部四位识别标记的动态码。该标记由平台随付款保留，付款人不需要填写；不是可切换的手工备注模式。建码 UUID 保存为渠道订单号；真实付款 `orderNo` 才作为渠道交易号，缺失时保持空，列表流水 UUID 只用于稳定事件键。通过详情 `tranExtend`、方式、金额和时间共同匹配。

### 拉卡拉缴费易

- 缴费易商户 ID、缴费易收银台名称：用于动态建码。
- 工作台商户号：必填，用于工作台选择收款主体和查询流水，不能用缴费易商户 ID 替代工作台商户号。
- 完整商户名称：可选，填写后与平台返回名称一致才匹配，留空不按名称筛选；默认商户也执行相同规则，名称缺失不能绕过已填写条件。最终仍须唯一定位商户。
- 收款终端号：可选；填写后只匹配该终端。
- 查询间隔：默认 3 秒。

图鉴用于登录滑块。动态二维码使用平台返回的 `payUrl`，其中 `payOrderNo` 与工作台流水 `tranAcpOrdNo` 对应。这个受理订单号写入渠道订单号；未取得独立的真实交易号时，渠道交易号保持空，不把受理单号重复冒充交易号。本地付款窗口使用原订单期限，不宣称可以远程关闭平台二维码。

### 星驿付驿汇客

- 使用星驿付主平台账号、密码。登录后免登驿汇客，按当前商户 `deptId` 处理。
- 收款有效期：默认 300 秒，允许 60～1800 秒，受原业务单期限限制。
- 查询间隔：默认 5 秒。

图鉴识别登录图片验证码。登录使用 SM2/SM4 协议，需要在 Web 与 CLI 使用的 PHP 中启用 GMP。依次创建、装修、发布收款页和读取二维码；中断后不重发结果未知的创建或变更。收款页标题使用本地支付号的 19 位数字部分，流水以标题、当前 `deptId`、金额、方式和时间匹配；`renId` 为渠道订单号，真实流水 `orderId` 为渠道交易号。

星驿付同时核对流水 `renPageId` 与原单收款页编号，不能只靠同名标题匹配。创建、装修、发布的最新进度保存后同步供当前调用使用；明确的认证/权限拒绝保留稳定阶段，其他变更结果不明保留进行中标记。已知页面的二维码读取失败保留页面和发布事实，恢复后只继续已知阶段，不重新建单。装修协议的 `copLikeQuery` 使用数字 0。

### 付呗收款单

- 收款门店 ID 或完整名称：单一门店可留空，多门店时必须唯一定位。
- 收款有效期：默认 300 秒，允许 60～1800 秒，受原业务单期限限制。
- 查询间隔：默认 5 秒。

本插件不需要图鉴。创建固定金额、限制一笔的收款单，标题保存完整本地支付号；以标题、`receiptId`、门店、金额、方式和时间匹配。`receiptId` 是渠道订单号，真实流水 `payOrderNo` 是渠道交易号。有效期控制本地识别窗口，不承诺平台二维码在同一时刻远程失效。

### 易宝易缴费

- 收款商户号：必填，当前登录账号必须有权限访问。
- 收款门店编号：只有一个可用门店时可留空，否则填写。
- 易缴费模板 ID：0 表示自动选择唯一有效模板，多模板时填写确切 ID。
- 模板只保留一个文本字段“缴费说明”，排序 1、不可修改、非必填。
- 收款有效期：默认 300 秒，允许 60～1800 秒，受原业务单期限限制。
- 查询间隔：默认 5 秒。

图鉴用于登录滑块；SM2 密码加密需要 PHP GMP。建单标题和缴费说明保存本地支付号的 19 位数字部分。通过标题、商户、门店和流水 `terminalNo` 对应的 `cashierNo` 匹配，仍核对金额、方式和时间。`cashierNo` 是渠道订单号，真实流水 `orderId` 是渠道交易号。

监听沿用默认 600 秒保活间隔复核缓存模板是否仍有效，复核时间独立于每轮查单成功时间；初次选定模板后不重复检查。失效后保留登录凭证，重新选择模板；明确指定的模板不可用时在运行维护中提示。这个时间只控制模板元数据复核，不是登录态缓存期限，也不为每笔付款追加模板请求。

## 故障排查与边界

后台现有“运行维护”显示采集错误来源、阶段、平台码和受限说明。未配置图鉴会在需要登录时、获取验证码之前提示，不阻止通道表单保存，也不影响已有有效凭证或其他无需图鉴的插件。识别仅发送一次请求，不自动重试消耗识别费用。

图鉴使用官方支持的 HTTPS。当前实现沿用公共 SDK 单次 10 秒、账号 15 秒、插件 30 秒的预算，登录全部步骤共用截止时间。[图鉴官方接口说明](https://www.ttshitu.com/docs/index.html)建议识别请求预留 60 秒；本版本保持上述请求上限和监听预算，不扩大等待时间。较慢的识别或多步骤登录可能在当前预算内失败；本轮截止耗尽记为 budget_exhausted，其他网络异常记为 network_error，后台按现有错误合同记录；不能据静态检查认定实测可用。

五款插件统一复用 V1 已有异常：付款明确拒绝和结果未知分别处理，采集协议/认证错误保留分类；账号状态和恢复提示保存失败仍作为 RuntimeException 上抛，不包装为平台拒绝或空成功。仅 SDK 内增加明确的 LicenseException，入口将它转换为现有 PaymentDefinitiveException；没有新增平台异常层级。

付款时间仍按原秒/毫秒或完整日期格式读取，严格拒绝非法日期和缺失时间；Unix 秒直接按应用上海时区格式化，本地日期不重复指定时区。DateTimeImmutable 继续用于截止参数及严格解析；不以 Clock 当前时间代替平台付款证据。原交易锁、创建事实、监听退避和 10/15/30 秒预算保持。

五个插件不实现平台接口退款、远程关闭或 HTTP 收款推送。人工核对、原订单关闭、超时和商户通知沿用 V1 既有入口；本地关闭不证明第三方二维码已经失效。


| 现象 | 检查与处理 |
| --- | --- |
| 插件列表没有对应插件 | 检查插件入口的目录和大小写，刷新插件管理；公共 SDK 不会自动安装平台插件 |
| 提示 PHP/扩展缺失或版本不兼容 | 核对网站和 CLI 的 PHP 版本、NTS、ABI、加载路径及配套 libphpx；现有包只支持 PHP 8.4 Linux x86-64 NTS |
| 新建时提示授权错误 | 核对授权码、本站域名、插件范围、到期及服务器时间；已有订单的采集确认不受授权到期阻断 |
| 提示配置图鉴 | 在系统设置的验证码识别中填写账号、密码；只有登录确实需要验证码时才调用识别服务 |
| 提示缺少 GMP | 星驿付、易宝分别确认网站和监听所用 PHP 已启用扩展，按安装说明处理后重启 |
| 凭证未就绪或认证失效 | 查看运行维护详情，等待监听重新登录；付款请求不会同步登录，恢复提示也不保证下一笔立即成功 |
| 商户、门店、终端或模板不匹配 | 按配置表单与平台实际数据逐项核对；范围错误由插件报告，系统不猜测账号字段 |
| 建单结果未知 | 核对原单和平台记录，避免盲目重发或重复付款；不能把网络异常当作平台明确拒绝 |

本页说明功能和使用约定。本轮完成原生编译、隔离的源码/native 行为比对及 CLI/FPM 独立加载检查，没有部署业务站点或发起真实平台请求；不据此认定五个平台实际登录和收款均已验收。

## 开发参考

以下说明供插件维护者核对内部行为。日常使用按前面的配置和排查步骤操作即可。

### 付款与采集

每个插件独立负责账号分组、登录态缓存、凭证可用性、预登录提示及失败退避，直接使用已有 ThinkPHP `receipt` 缓存。登录态字段和提示格式是各插件的私有实现，不要求不同平台一致，也不由公共服务解释。原生 SDK 处理对应平台的请求、响应、认证、错误码及流水字段转换；PHP 插件提供当前候选的必要标题/页面投影，取得规范化流水后负责最终本地订单匹配。SDK 不访问 MPAY 数据库或直接推进订单。插件包不再依赖 `sdk/receipt` 共用协议或登录态类。

监听任务合并当前插件相同登录账号，保留 Cookie、Token 等状态，并按收款范围轮转。缓存文件不设置本地有效期；平台明确返回凭证失效时，监听任务清理该账号登录态，后续重新登录。平台明确给出的凭证到期时间仍须遵守。

付款请求只读取同账号、同凭证、同收款范围已经验证过的缓存，不在付款请求中登录、识别验证码或刷新认证。缓存缺失、凭证已变更、当前缓存属于其他收款范围或平台明确拒绝认证时，本次付款留下账号恢复提示并按原结果返回；已有平台创建事实的原单保留未知语义，不自动重发。检查采集状态并等待监听完成认证或范围选择后，再发起新订单。

付款提示与登录态分开保存，相同待处理提示不重复写。监听在已有调度中优先选择对应账号和范围，跳过正常 600 秒保活间隔，保留失败退避；无待核对原单时仍由原 prelogin 入口验证。它不会中断正在执行的平台请求，不能保证紧接着的下一笔订单已经恢复。登录态只有监听写入；旧失败只可否定它实际使用的那份快照，新提示不会因旧处理结果而被删除。

恢复提示内部的编号、凭证/状态摘要是缓存协作信息，不是需要管理员填写的配置字段，不改变五款插件的字段定义。提示按账号合并，不是逐笔订单队列。范围不匹配保留 Token/Cookie，重新选择范围；网络超时不直接清空凭证。平台错误解释留在各自 SDK：例如不同平台的 HTTP 403 可以表示不同含义，不能由公共服务统一推断。

恢复摘要只记录本平台实际付款使用的认证身份：付呗为 access_token 与 JSID，天阙和拉卡拉为 token，驿汇客为 yhk_token，易宝为 X-Wx-Id。商户范围仍单独核对，模板复核时间、到期元数据及展示名称不参与摘要；易宝 Cookie 续期不代表 X-Wx-Id 已更新。辅助状态更新不会吞掉同一失效凭证的恢复提示，新凭证也不会被旧失败清除。缓存永久保存、平台到期检查和验证码配置入参继续保留。

同一账号多个范围共用登录态，每轮只查询其中一个范围；范围轮转也受账号查询间隔限制。平台会话当前绑定哪个商户，由插件按平台协议处理。不要把某一范围的认证成功理解为所有范围均已可以立即下单。

重复账号允许保存通道配置；同一插件账号存在互相冲突的密码时，由插件在采集阶段记录配置冲突，不轮流重复登录。管理员根据后台错误核对、停用或修正相应通道。

创建请求发出前，插件在现有订单扩展中保存本次创建事实。网络中断、超时或成功响应缺少关键结果时，不把未知结果当作平台拒绝，也不盲目重复创建。已取得完整二维码的原单复用原材料和有效期；星驿付只在已有确定阶段上继续剩余步骤，不重发结果未知的变更。

创建接口的业务判断留在各平台 SDK，沿用现有 PaymentDefinitiveException 表达明确拒绝；插件只在原执行有效时保存拒绝事实，不根据通用诊断中的 HTTP 状态或非空错误码猜测付款结果。四款单步创建采用下表规则，认证、权限及非 JSON 响应仍分别按各平台已有约定解释。

| 平台创建接口 | HTTP 200 下的业务约定 | 缺失或矛盾信息 |
| --- | --- | --- |
| 付呗 receipt.web.receipt.add | success=true 成功；success=false 明确拒绝，不伪造 errorCode | 缺失 success 或成功响应缺少 receiptId 保留未知 |
| 天阙 createQRCode | code=0000 且 success 不为 false 才成功；其他非空业务码按接口拒绝处理 | 缺失 code、成功码与 success=false 冲突、成功响应缺少地址/UUID 保留未知 |
| 拉卡拉缴费易 /cashier/pay | JSON code=200 成功，其他非空业务码明确拒绝；不使用工作台登录态 | 缺失业务码或成功响应缺少有效 payUrl/payOrderNo 保留未知 |
| 易宝 /cashier/info | JSON code=00000 成功，其他非空业务码明确拒绝 | 缺失业务码或成功响应缺少 cashierNo 保留未知 |

星驿付普通业务错误继续保留未知；只有尚未创建页面且明确认证/权限拒绝时标记创建拒绝。已有页面的装修、发布、取码失败继续保留已保存编号及阶段，不改为全单失败或重放未知步骤。网络中断、非正常 HTTP 响应及无法解析的响应不以“存在错误码”直接推断为创建拒绝。

监听每账号每轮只读取第一页最新最多 200 条流水，并携带订单时间范围，不翻页补齐。达到条数上限会显示覆盖限制。天阙的列表没有足够的动态码识别依据，只对本批有候选订单的成功流水补查详情；这会额外产生详情请求，不属于列表翻页。预登录只做小量验证查询，正式查单已处理的账号本轮不再额外探测。

付呗先按本轮订单标题筛选记录，星驿付先按本轮标题和收款页编号筛选记录；无关流水不进入本地订单字段校验。星驿付不支持的支付方式跳过，相关流水的金额、时间、交易号和归属检查保留。预登录只核验平台认证及真实查询响应，不转换、投递业务流水。

插件对完整批次按通道、方式、金额、原付款窗口和平台标识匹配，返回零笔、一笔或多笔标准成功结果。公共生命周期沿用原事务、归属、流水防重和商户通知机制，逐笔确认；只保存最终成功绑定的真实流水。匹配有歧义时跳过并记录技术日志，不任意选择订单。

### 动态码展示

五款插件统一返回 `page/dynamicReceipt`，公开参数只包含 `_page` 和 `payment_url`。payment_url 只用于生成二维码，不作为页面跳转或复制目标；订单金额和付款期限仍使用公共收银台数据，不把后台认证或整个订单扩展公开。

动态码与静态码、API 二维码使用同一套指引：PC 展示二维码并提示手机扫码；微信内的微信订单、支付宝内的支付宝订单提示长按识别，不显示地址按钮；普通手机浏览器、错误或未识别的支付应用提示切换，并显示“复制地址”。复制的是当前订单的本站收银台地址，保留访问凭证，换应用后仍访问原订单；不是 payment_url，不再自动打开平台页面。云闪付等未识别环境使用通用移动端指引，不构造 App 唤起协议。

复制失败时显示可手动选择的链接；存储不可用时保留人工打开。到期或公共流程撤下付款区后停止跳转和操作。第三方不提供支付后返回能力时，不补造返回参数；后台正常确认和通知，用户返回原页后继续查询。

### 私有源码调试

插件开发工作树在项目根 composer.json 中登记 `"mpay\\premium\\": "premium_sdk/src/"`，执行 `composer dump-autoload --no-scripts --no-plugins` 后，由 ThinkPHP 原有 vendor/autoload.php 加载源码。没有单独的开发加载文件、嵌套 Composer 或启动参数；IDE 同样读取根映射并索引源码。

命名空间与路径采用一致的小写形式，例如 mpay\premium\fubei\Client 对应 premium_sdk/src/fubei/Client.php；类名与文件名保持大驼峰，遵循 [PSR-1](https://www.php-fig.org/psr/psr-1/) 和 [PSR-4](https://www.php-fig.org/psr/psr-4/)。基目录的下划线是本项目风格与用户偏好，不宣称 PSR 强制使用某一种分隔符。

源码调试和扩展运行都要求 PHP 8.4+，不设低版本或免授权例外。源码调试不要同时加载该原生扩展；正式发布只交付 .so 配套包和 PHP 插件入口，不需要客户更改 Composer。根映射只保存在本地插件工作树，依赖清单与公共版保持一致，没有新增依赖库。

SDK 修改阶段默认只做语法和静态检查，不要求每次编译。维护者复用已保留的 mpay_typephp Docker 构建容器，在需要交付新版扩展时才执行构建；容器启动本身不会编译。客户运行插件只需要发布包及相应 PHP 环境，不需要这个构建容器。
