# 易支付平台接入

本页适用于你已经有第三方易支付 V1 平台的商户账号，希望让 MPAY 通过该平台收款的情况。如果是让自己的商城接入 MPAY，请看[业务网站接入](V1-15-业务网站接入.md)。

两套凭证分别使用：**第三方平台的 PID/KEY 填进 MPAY 通道；MPAY 应用的 PID/KEY 填进你的商城。**

## 1. 准备平台资料

从第三方平台取得网关地址、商户 PID 和 KEY，确认该账号已经开通需要的支付宝或微信支付。MPAY 服务器、付款浏览器及第三方平台需要能访问各自的接口和回调地址。

## 2. 新增通道并填写参数

1. 打开 **插件管理**，确认“易支付 V1”插件已存在并启用。刚更新代码时，先点击“刷新插件列表”。
2. 打开 **收款配置 → 新增通道**，选择“支付宝”或“微信支付”，再选择“易支付 V1”。
3. 填写通道名称、金额范围；首次可保留高级策略默认值。
4. 到“插件参数”填写下表，核对后点击 **保存并启用**。

| 字段 | 填入什么 |
| --- | --- |
| 第三方网关地址 | 平台提供的根地址，例如 `https://upstream.example.com/`；平台装在子目录时保留该子目录，不添加 submit.php、mapi.php、api.php 或查询参数 |
| 第三方商户 PID | 第三方平台给你的商户编号，不是 MPAY 应用 PID |
| 第三方商户 KEY | 与上述 PID 配套的第三方密钥，不是 MPAY 管理员密码或应用 KEY |
| 下单方式 | 首次使用默认“页面支付（submit.php）”；只有平台支持并需要 API 下单时，才选“API 下单（mapi.php）” |

保存后通道自动加入对应默认轮询组。想同时提供支付宝和微信时，分别建立对应通道；第三方账号可以相同，但要分别确认已经开通该支付方式。

## 3. 两种下单方式怎么选

| 下单方式 | 付款时会发生什么 |
| --- | --- |
| 页面支付（submit.php） | 买家从 MPAY 前往第三方收银台，按平台页面付款 |
| API 下单（mapi.php） | MPAY 服务器向平台下单，再按返回结果展示付款链接或二维码 |

付款成功后由第三方平台通知 MPAY，MPAY 再通知你的业务网站。平台回调地址由插件随订单提交，不用配置手机通知转发。保持[原有两个后台任务](V1-18-部署与后台任务.md)运行，不需要另建平台查单任务。

## 4. 核对第一笔订单

1. 在该通道点击 **更多 → 测试**，选择应用和一笔符合平台要求的小额金额。
2. 核对第三方收银台的收款方、商品和金额，再完成付款；这是实际付款，不会自动退款。
3. 在第三方平台查看原交易，确认到账；返回 MPAY 的 **交易订单**，找到同一笔订单。
4. 确认 MPAY 显示支付成功，查看平台订单号和处理记录。此类订单可以没有“到账流水”。
5. 再从你的业务网站完成一笔订单，核对 MPAY 的商户通知和业务网站处理结果，详见[第一笔收款](V1-04-完成第一笔收款.md)。通道测试没有外部通知地址，不能代替这一步。

## 常见问题

| 现象 | 怎么处理 |
| --- | --- |
| 找不到“易支付 V1” | 在插件管理刷新列表并启用，再回到新增通道 |
| 网关地址校验失败 | 删除末尾接口文件名和查询参数，保留平台根地址或实际安装子目录 |
| 平台提示商户、签名或方式错误 | 核对通道里的第三方 PID/KEY，以及平台是否开通当前支付方式 |
| 平台已收款，MPAY 仍未成功 | 检查平台回调发送记录和 MPAY 通道回调日志；平台必须能访问该订单的 MPAY 通知地址，不要让买家再次付款 |
| MPAY 已成功，商城未更新 | 打开原订单“商户通知”，按[通知排查](V1-10-商户通知与人工处理.md)处理 |
| 下单超时或提示结果未知 | 先核对 MPAY 原单与平台记录，保留原订单号，不盲目换号重付 |
| 需要退款 | 第三方平台须支持并已开启接口退款，再按[退款接口](V1-16-易支付V1接口参考.md#退款申请)操作；关闭订单不会退款，退款结果未知时先查原记录 |

需要开发或修改此插件时，再阅读[接口与内部处理约定](V1-23-支付插件开发.md#9-易支付-v1-第三方平台插件)。
