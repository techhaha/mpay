# Android 监听助手

MPAY 监听助手是独立运行的 Android 客户端。配置、规则、日志和帮助保存在手机本地；
仅向用户配置的接收地址发送命中的收款通知，以及手动启用后的心跳。

当前客户端版本为 **1.0.0-rc3**，属于真机验收版本。安装包由维护者交付，尚未上架应用商店。
客户端源码使用独立 Git 仓库维护，本地开发目录为 `clients/android`，不包含在 MPAY 后端仓库中。
构建通过和静态检查不代替手机实测或真实收款验收。

## 安装要求

- 最低 Android 8.0（API 26），能正常安装 Android APK。
- 手机需要支持并允许授予“通知读取权限”。
- 来源应用必须正常产生通知栏收款消息。
- 首版内置微信、支付宝收款规则；其他应用可添加自定义规则，但接收端也必须支持相应来源。
- 系统标记为低内存的 Android 10 及以下设备、工作资料空间和同包名分身存在系统限制，
  不仅凭系统版本承诺可用。请以目标手机验收结果为准。

应用不依赖 Google Play 服务、SIM 卡或 Root。普通应用图标和名称从系统读取，
不下载远程图标；无法读取已卸载应用时使用通用图标并保留历史包名。

## 第一次使用

1. 在 MPAY 后台配置对应的微信或支付宝手机监听通道，准备该通道的通知地址和通知密钥。
2. 安装客户端，在“我的 → 转发通道 → 添加”填写名称、地址、密钥。
3. 选择实际安装的收款应用及对应内置规则，保存通道。
4. 在“我的 → 运行设置”开启通知读取权限，检查本工具通知权限、电池优化及后台运行设置。
5. 返回首页开始监听。通道已启用、通知权限有效且系统监听服务已连接时才显示“监听中”。
6. 先在后台发起待付款订单，再完成实际小额付款，分别查看客户端日志与 MPAY 后台订单结果。

新安装的客户端没有演示订单或虚构日志。初始监听关闭，心跳关闭。

### 通知地址与密钥

支持合法 HTTP/HTTPS 地址、域名、IPv4、IPv6 和非标准端口。IPv6 URL 使用方括号。
保留 HTTPS 证书校验；请填写最终接收地址，客户端不跟随跳转转发敏感通知。

通知密钥与后台手机监听通道中的密钥保持一致，不是商户 PID/KEY。
编辑已有通道时回填实际密钥，可通过眼睛按钮显示、隐藏并直接修改。
保存时使用输入框当前值，清空不代表保留旧值；启用通道必须填写密钥。
导入的通道没有密钥，填写后才能启用。

### 成功响应

当前 MPAY 微信、支付宝手机监听插件成功正文为纯文本 `200`。
客户端默认要求 HTTP 2xx 且正文去除首尾空白后完全等于 `200`。

在通道高级设置中，可以按接收平台约定修改“成功响应正文”，例如 `success` 或 `ok`。
首版是纯文本精确比较，不做包含匹配、脚本或 JSONPath 判断。

HTTP 200 加 `400：来源消息认证失败`、错误 HTML 或其他正文，仍然是失败。
“转发成功”代表接收端返回了约定的确认，不等于商户的业务流程已经全部完成。

## 三个页面

| 页面 | 用途 |
| --- | --- |
| 首页 | 运行状态、今日计数、监听应用和最新三条日志 |
| 日志 | 查看结果，按状态、日期、应用、通道筛选，打开详情 |
| 我的 | 通道、规则、运行设置、设备名称、备份、帮助及项目地址 |

日志卡片显示应用图标、原始标题和消息、状态、识别金额、时间及结果说明。
卡片不显示通道信息，完整通道与请求信息放在详情中。有效期内的可重试失败才提供重试按钮。

统计按“通知 × 通道”记录计算，同一条记录重试不会增加总数。
待发送及发送中的记录显示在“全部”，不计入失败。客户端金额不是后台财务账目。

筛选中的日期、应用和通道放在同一个底部面板，“全部/成功/失败”状态切换常驻。
应用与通道均使用单选列表；应用来自已启用通道并按包名去重，切换应用会清除原通道选择。
日期使用紧凑的开始/结束日期，选择后返回筛选面板，点击“应用筛选”才查询。
三个状态的数量使用同一组日期、应用和通道条件计算。

## 规则编辑

用户通过表单编辑，不需要手写 JSON：

1. 选择监听应用，填写规则名称。
2. 添加通知类型，选择指定标题、标题正则或不限标题。
3. 指定从通知标题还是正文提取金额，选择常见模板或填写高级表达式。
4. 金额捕获组通常保持 1。
5. 使用本地试运行检查实际标题、正文和提取金额。
6. 通知类型页面点“完成”，最终在规则页面“保存规则”。

每条规则可有多个通知类型，按顺序取第一个完整命中的结果。
内置规则只能查看、试运行或复制为自定义规则。用户自定义规则不随 APK 更新被覆盖。
使用 RE2 正则，不支持环视、反向引用或脚本。非法表达式不会被保存或自动降级匹配。

支付宝“你已成功收款0.10元”从标题提取，不能把正文“1元红包”当成收款金额。
试运行不会发送请求，不会创建后台订单。

## 发送、重试和过期

- 首次收到通知时固定原始内容、设备信息、客户端版本、时间戳、签名及目标地址。
- 同一通知在每个通道内去重，不以“金额相同”合并不同笔收款。
- 自动、手动和进程恢复的重试都复用原请求，不刷新时间戳。
- 客户端窗口最多 30 秒，总发送次数最多 3 次。接收端可以配置更短的时间容差。
- 网络异常、HTTP 5xx 或 429 可在窗口内自动重试；明确业务拒绝不自动循环重发。
- 超时后保留日志供核对，不在网络恢复后把旧通知当新通知补发。
- 成功、超过次数上限、已过期或已停用通道的记录不能继续重试。
- 不扫描并重放重连前的全部通知；收到的历史通知只记录已过期结果，不发送。

请求结果未知不代表实际没有收款，遇到网络超时请核对后台。
日志中可以查看原始消息、客户端金额、HTTP 状态和响应内容；复制请求会隐藏签名。

## 心跳与后台运行

心跳默认关闭。开启后，收款通知和心跳都发往通道已经配置的同一个 notify 地址，
共用密钥和成功响应正文，不需要另配地址，也不推导其他路径。

客户端约每分钟向启用通道上报一次。正文携带 listening 布尔值，true 表示正在监听，
false 表示当前未在监听；开启心跳后，暂停监听也可继续上报 false。系统休眠或网络异常可能延迟。
心跳不积压、不补发、不进入收款日志，失败不自动关闭通道。
“检查连接”同样只发送一次心跳，不发送模拟到账。

MPAY 后端需部署新版 notify 处理。通过原有来源、签名和时间校验后，
依据 listening 字段是否存在区分心跳；没有该字段的收款通知沿用原处理链路。

后台在原“运行维护 → 通道运行状态”列表查看心跳正常、未在监听或心跳超时，
最近活动显示有效心跳的服务端接收时间，详情展示设备、客户端和应用。
此前上报正在监听且超过 180 秒没有心跳时显示超时；明确上报未监听则保留该状态。
没有上报记录时显示等待通知推送。心跳不证明支付应用已登录或实际收款一定可用。

本轮没有外部掉线通知，也不会按心跳自动停用通道。关闭心跳上报后，
服务端无法区分主动关闭和断网，因此此前的正常心跳可能随后显示超时。

| 设置 | 实际作用 |
| --- | --- |
| 通知读取权限 | 允许读取其他应用通知，是监听的必要条件 |
| 应用通知 | 控制本工具自己的运行通知是否可见 |
| 电池优化 | 部分减少休眠对后台处理的限制 |
| 自启动与后台运行 | 按厂商设置指引操作，无法统一确认时显示“去设置” |

部分 Android 13 及以上系统需要在应用信息中允许受限制的设置，才能授予通知使用权。
应用无法代替用户完成系统授权。普通状态通知不保证永久保活，系统强行停止后请重新打开。

## 数据和备份

默认保留最近 7 天日志，可改为 30 天。清理只影响本机已结束记录，不改变服务器订单。
通知密钥以明文保存在应用私有空间，不使用额外加密层；应用关闭系统自动备份。

配置导出包含通道和自定义规则，不包含密钥、签名和转发日志。
导入需要确认，会替换配置；导入通道保持关闭，重新填写密钥和检查权限后再启用。
卸载前请按需导出配置，升级应使用相同包名和签名的安装包。

## 真机验收

本轮不运行独立单元、仪器或交易测试，由用户进行实际验收：

- 窄屏、普通手机、平板、横竖屏及分屏下，检查表单、底部按钮和日志卡片。
- 开启较大系统字体，确认没有遮挡、文字截断导致操作无法完成或键盘盖住保存按钮。
- 微信各通知标题、支付宝标题收款及正文红包场景，分别检查金额来源。
- 正常送达、HTTP 200 业务拒绝、短暂断网、超时、重复通知、关闭通道。
- 锁屏、应用退到后台、系统重启、重新授权、应用升级保留配置。
- 自定义规则、备份导入导出、日志筛选、详情与原始请求。

界面使用 dp/sp、系统安全区和可滚动内容，宽屏居中限宽；
实际机型的系统权限入口与后台保活效果，以真机结果为准。

## 覆盖升级

1.0.0-rc3 使用原包名和签名，可覆盖安装，勿先卸载或清空应用数据。
本开发版将通道表的密钥字段改为明文，不转换旧开发版的加密值；
首次升级会清空旧密钥并关闭对应通道，需要在编辑通道中重新填写密钥并启用。
地址、规则、设备偏好和现有日志保留，日志保留期仍按用户设置执行。
新版本保存的密钥会原样回填，之后正常查看和修改即可。

升级后系统可能重新连接通知服务，返回首页核对权限和实际监听状态。

## 界面与切换

- 首页、日志、我的直接切换，没有滑动、淡入淡出或内容渐显；各页分别保留滚动位置。
- 子页面背景、顶部栏、内容和底部操作作为整页从右侧进入，约 240ms。
  背景和顶部栏始终不透明，内容在滑入过程中同时渐显，到位时已经完整显示。
- 返回时整页向右退出；前一页直接恢复，不再重复渐显。
- 名称、地址、密钥等输入统一使用上方标签和下方输入框。
- 同组列表保留与文字左侧对齐的浅色细分隔线，组间留白；不在图标下方画线。
  分组容器不增加上下内边距，首项、末项与中间项采用相同行内留白。
- 普通单行列表最小高度 56dp，含说明的列表最小高度 72dp，三行通道列表最小高度 88dp；
  长文字或系统大字体可自然增高，不以固定高度裁切。
- 保存操作栏、底部导航和首页统计不增加装饰分隔线，日志内容与结果之间保留一条细线。

功能图标使用随 APK 打包的 Lucide 矢量，应用图标继续从系统读取。
横屏或较小高度的日期面板使用同套日期输入控件，避免日历和确认按钮互相挤压。
